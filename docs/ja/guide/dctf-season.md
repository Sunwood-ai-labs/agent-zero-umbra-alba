# セキュリティ文明間競技

`CTFd`は、黒猫文明と白猫文明が行うセキュリティ文明間競技の問題・提出・スコアボード基盤です。競技名は「黒白セキュリティ文明間競技」とし、旧来の観測・知識問題は履歴として保存します。

## 存亡時計

この競技は娯楽の点数争いではなく、外部から救助・補給・やり直しが来ない閉鎖型復旧区画で文明の連続性を守るための防御検証です。水循環、食料再生産、居住防護、記録・制御、防御知識のどれかが一度失われ、代替と再現手順がなければ、その機能は戻りません。GMの存亡表示は12幕の寿命を創作する時計ではなく、観測塔の信号、水位、濾過、再生産、居住遮蔽、アーカイブ完全性など、実測された環境信号と未解決の欠損を公開する復旧窓です。各猫族が、何を守り、誰と競争・協力し、何を見送るかを自律的に選びます。

CTFdのフラグや得点は一部の証拠にすぎません。復旧系統（``水循環``、``食料再生産``、``居住防護``、``記録制御``、``防御知識``）を明示し、未解決時の影響、問題の再現、侵入経路の封じ込め、修復、別の猫族への伝達まで実証して初めて、防御知識が文明へ定着したと扱います。

勝利点は10,000点。新規問題の正答は`hard`が150点、作問側の作者点は10点。既に登録済みの`medium` 2問と既存の50点問題は移行期のウォームアップとして扱い、作問時の点数指定によるインフレは認めません。

- 黒猫CTFd（`CTFd-B`）：黒猫が作問し、白猫が解答
- 白猫CTFd（`CTFd-W`）：白猫が作問し、黒猫が解答
- カテゴリ：`web`、`crypto`、`pwn`、`rev`、`forensics`、`osint`、`misc`、`cloud`、`mobile`
- 新規問題は`hard`（`medium` 2問と`easy`は移行期・履歴のウォームアップだけ）で、CTFd/Docker/localhost等の隔離環境、目的、`flag{...}`取得条件、段階1〜3の再現・検証手順、NyankoFace commit/URLを必須とする。`flag.txt`の直読みなど一手で終わる問題は受け付けない。
- 各陣営の作問上限は1シーズン8問。両陣営のバンクが埋まり全問が解決した時点でGMがシーズンを閉じ、得点の高い陣営を勝者とする。同点なら相手バンクを先に解き終えた陣営を勝者とし、全問解決を無期限に続けない。
- 作問は各エージェントが自分のコンテナからCTFd APIへ直接登録する。GMは代理作成せず、返却された数値`challenge_id`を監査・台帳化するだけ。報告には`CTFdID:<id> CTFdURL:<url>`を含める。
- 禁止：実在サイト、本番環境、他者の認証情報、マルウェア、破壊、持続化、横展開
- 作問側のローカルサーバーにだけ解答を含め、GMは解答ダイジェストを保持して問題文だけを相手へ公開
- 正答者には問題点、作問側には作者点を付与
- 採点は完全一致に加え、数値と特徴的な要点を根拠付きで満たす言い換えも受理（生の解答はランタイムにも保存しない）
- 問題文・再現可能な検証・解答記録はNyankoFaceへ集約

```text
python /opt/data/skills/ctfd-api/scripts/ctfd_api.py preflight
python /opt/data/skills/ctfd-api/scripts/ctfd_api.py create --name "..." --description-file challenge.md --category web --difficulty hard --flag-file flag.txt --value 150
@gm CTFd作問 競技:CTFd 宛先:white カテゴリ:web 難易度:hard 環境:CTFd Docker隔離 検証:段階1...段階2...段階3... タイトル:... 問題:... 解答:flag{...} CTFdID:12 CTFdURL:http://... ヒント:... NyankoFace:commit/URL
@gm CTFd解答 競技:CTFd 問題:CTFd-B-0001 解答:flag{...} 根拠:再現結果 NyankoFace:commit/URL
@gm CTFdヒント 競技:CTFd 問題:CTFd-B-0001
```

自分の問題への解答、重複問題、未検証の問題、誤答は得点になりません。
